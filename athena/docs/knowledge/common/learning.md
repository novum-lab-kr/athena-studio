# 학습 기준 (학습 루프)

에이전트와 배우기 검토자(`scripts/learn-review.mjs` · 역할 `.claude/agents/learn-reviewer.md` — 내 작업의 PR 이 머지되면 돈다)가 **같이 읽는 기준**이다. 작업에서 알게 된 것을 각 공책(`docs/knowledge/<영역>/gotchas.md`)에 넣을지 판단하고, 넣을 거면 어떻게 적을지 정한다. 흐름은 `AGENTS.md` 6절 "📚 배운 것" · 언제 올리고 어디에 담는지는 8절.

## 1. 무엇을 학습하나 — 아래를 모두 만족할 때만

- **다시 마주친다** — 그 레포에서 평범한 다음 FE 작업(화면·기능·버그 수정)을 하다가 또 만날 가능성이 높다
- **모르면 실제로 잘못된다** — 잘못 고치거나, 사고(실제 요청이 나감·데이터가 바뀜)를 내거나, 시간을 크게 버린다. "모르면 무엇이 잘못되나"를 구체적으로 한 줄 쓸 수 있어야 한다. 못 쓰면 학습하지 않는다
- **코드만 봐서는 바로 알기 어렵다** — 여러 파일·설정·외부 동작이 얽혀 있거나, 문서와 코드가 다르다

**대부분의 작업은 학습할 게 0개다. 그게 정상이다.** 억지로 만들지 않는다. 한 작업에서 많아야 3개.

## 1-1. 코드로 확인되나 — 사실과 취향을 가르는 기준

학습은 **누가 작업해도 똑같이 밟는 코드 사실**만 담는다(공책은 팀이 같이 쓴다). 사람마다 다른 일하는 스타일은 Claude Code 메모리 몫이다. 둘을 "사실인가 취향인가"로 판단하지 않고, **근거가 어디에 있나**로 가른다.

| 근거 종류(`basis`) | 뜻 | 학습하나 |
|---|---|---|
| `code` | 코드·설정·문서에서 확인된다(파일:줄) | ✅ |
| `run` | 실행 결과로 확인됐다(에러 메시지·요청 기록·테스트 결과) | ✅ |
| `user-said` | 사용자가 그렇게 말한 것뿐이다 | ❌ — 취향일 수 있다. 메모리가 맡는다 |

사용자 교정에서 나온 것도 **코드나 실행 결과로 뒷받침될 때만** 학습한다. 사용자 말만 있으면 학습하지 않는다 — 검토자 답에서 `basis: user-said` 는 스크립트가 기계적으로 버린다.

**헷갈리는 예**

| 후보 | 근거 | 판단 |
|---|---|---|
| 채팅 앱 FE TC 는 쓰기 요청을 mock 으로 막아야 한다 | `code` — QA 실행기는 요청을 알아서 막지 않는다(`scripts/qa/cases.mjs`) | ✅ 학습 |
| 패키지에 새 import 경로를 열면 lint 허용 목록도 고친다 | `run` — 소비 앱에서 lint 에러가 났다 | ✅ 학습 |
| 이 레포 날짜는 `formatKst` 유틸로 바꾼다 | `code` — 다른 방식이 섞이면 시간대가 틀리는 줄이 있다 | ✅ 학습 |
| 이 레포 날짜는 `formatKst` 유틸로 바꾼다 | `user-said` — "그거 말고 formatKst 써" 만 있고 코드상 이유를 못 찾았다 | ❌ 취향일 수 있다 |
| 결정은 표로 보여 줘 · pane 에 띄워 줘 · 요청한 것만 해 | `user-said` | ❌ 일하는 스타일 — 메모리 |
| 커밋 메시지는 한국어로 | `code` — 레포 규칙 문서(`rules.md`)에 이미 있다 | ❌ 이미 있음 — 새로 넣지 않는다 |
| 질문 직후 "새 채팅"을 누르면 질문이 빈 채로 전송된다 | `run` — 요청 기록 | ❌ 앱 버그 — 고치면 사라진다. 이슈로 |
| 옛 lint 설정의 내부 경로 금지 규칙은 사실상 꺼져 있다 | `run` | ❌ 새 설정으로 옮기는 중에만 맞는다 |

## 2. 학습하지 않는 것

- **이번 작업에서 이미 코드로 고친 버그·누락** — 이제 코드가 막아 주니 기억할 필요가 없다
- **아직 안 고친 버그·설계 문제** — "질문이 빈 채로 전송된다", "웹에서 이 버튼이 반응이 없다"처럼 **고치면 사라지는 것**은 배울 게 아니라 고칠 것이다. 이슈(`issues/`, `kind: code`)로 남긴다. 함정은 "코드가 원래 그렇게 생겨서 앞으로도 조심해야 하는 것"이다
- **옮기는 중에만 맞는 것** — 라이브러리·설정 전환처럼 끝나면 의미가 없어지는 사실. 전환이 끝나면 낡은 줄이 된다
- **한 번 있었던 장애·문의·조사 결과** — 재현·원인 규명 이야기
- **원인이 FE 레포 밖**인 것 — 서버·인프라·CDN·외부 서비스
- **이번 작업에서 만든 도구·스크립트 자체의 구현 세부**
- **그 작업의 요구사항·결정·진행 경과**, 일반 상식·일반 프레임워크 지식
- **"X 는 안 된다" 같은 단정** — 그때 환경 탓일 수 있다. 조건을 붙이거나 적지 않는다
- **환경 탓 실패**(네트워크·권한·로컬 설정·**Node·pnpm 버전**·설치 상태), **해결 못 한 실패를 정답처럼** 적기
- **사용자 선호·일하는 스타일**(말투·보고 형식·작업 방식) — Claude Code 메모리가 맡는다(`AGENTS.md` 2.5). 근거가 사용자 말뿐인 것은 모두 여기로 본다(1-1)

## 3. 어떻게 적나 — 있는 그대로 옮기지 말고 쉽게

학습 후보는 이슈(`issues/<날짜>-<영역>-learn-<이름>.md`)로 올라가 현황판 **[학습] 탭**에 뜬다. 사용자가 읽고 [넣기]를 누를 수 있게, **그 작업을 모르는 사람이 봐도 알 수 있게** 쓴다.

| 칸 | 쓰는 법 |
|---|---|
| 제목 | 무엇을 학습했는지 쉬운 한 줄. 파일명·함수명 대신 "무슨 일이 생기나"로 |
| `## 무엇을 배웠나` | 2~3문장. 배경부터 짧게 → 무엇이 함정인지. 전문 용어·약어는 풀어서. 대화·로그 문장을 그대로 붙이지 않는다 |
| `## 왜 중요한가` | 모르면 다음 작업에서 무엇이 잘못되나 한 줄 |
| `## 공책에 넣을 문장` | 공책(gotchas)에 실제로 들어갈 한 줄 — **규칙 + 이유 한 마디**. 에이전트가 작업 전에 읽고 바로 행동할 수 있게. PR 번호·날짜·작업 이야기는 빼고 필요하면 파일 경로 |
| `## 어디서 배웠나` | 어느 작업(계획서)에서, 무엇을 보고(파일:줄·확인한 사실 한 줄). 비밀값·긴 인용 금지 |
| front matter `basis:` | 근거 종류 `code` · `run`(1-1). `user-said` 면 후보를 올리지 않는다 |
| front matter `scope:` | 어디에 걸리나(7절) — 그 화면을 만질 때만 걸리면 코드 폴더(`app/orders`), 레포 어디서든이면 생략 |

**예** — 좋은 것 / 나쁜 것

> 제목: 채팅 웹 FE TC 는 쓰기 요청을 직접 막아야 한다
> 무엇을 배웠나: FE TC 는 화면을 실제 브라우저로 눌러 보는데, 실행기는 데이터를 바꾸는 요청을 알아서 막아 주지 않는다. 그래서 TC 마다 직접 막아야 한다.
> 왜 중요한가: 모르고 TC 를 짜면 서버에 실제 질문·설문·탈퇴 요청이 나가 테스트 계정 상태가 바뀐다.
> 공책에 넣을 문장: 채팅 웹 FE TC 는 질문·피드백·이름 바꾸기·설문·탈퇴 REST 요청을 `mock` 단계로 막는다 — 실행기는 요청을 알아서 막지 않는다.

> ❌ "minimatch 3.1.5 는 맨 앞 `!` 를 패턴 전체 부정으로 읽어 `'!(@repo)/**/*'` 가 …" — 원문을 옮겨 적어 처음 보는 사람이 무슨 일인지 모른다

## 4. 중복이면 새로 쓰지 않는다

먼저 그 공책과 열린 학습 후보를 찾아본다. 이미 있으면 새 줄이 아니라 **기존 줄을 더 정확하게 고친다** — 후보 front matter 에 `strengthen: <공책에 적힌 그 줄 그대로>`(앞의 `- `·`<!-- learn:… -->` 표시는 빼도 된다). 정확히 같은 줄만 고치고, 못 찾으면 [넣기]가 거부한다. 그 줄이 이미 학습으로 들어온 줄이면 새 학습이 아니라 **그 학습 기록에 이어 붙는다**. 같은 대상의 열린 후보가 있으면 거기에 덧붙인다.

## 5. 반복 절차는 스킬 후보

같은 절차를 손으로 다시 하게 되면 `target: skill:<이름>` 후보에 "반복 +1"을 덧붙인다. 2회 이상이면 "🛠 스킬로 만들까요?" — 스킬은 사용자가 고르면 아테나가 만든다(`docs/extending.md` "학습으로 스킬 만들기").

## 6. 저장·승인

- 에이전트·검토자는 **공책을 직접 고치지 않는다.** 후보만 올린다
- 공책은 **각 영역의 `gotchas.md`** 다(모든 작업이 다 읽는 파일 — 나뉘면 화면 파일 `gotchas/<폴더>.md` 가 붙는다, 7절). patterns·workflows 에는 넣지 않는다. `target` 의 `#절` 은 같은 대상 후보를 합칠 때만 쓰고, 넣을 때는 공책 끝 `## 학습` 절로 들어간다(`scope` 가 있으면 7절)
- **새 후보(이슈)를 여는 기준 (2026-10-30)** — 너무 많이 열면 사람이 못 따라가 공책에 거의 안 들어갔다(5일에 72개 → 공책 몇 줄). 그래서 배우기 검토자는 **실행으로 확인한 것(`basis: run`)** 이나 **같은 함정이 두 번째 나온 것**(`repeatOf`)일 때만 새 이슈를 연다. `basis: code` 한 번짜리는 이슈 대신 `.sync/learn-seen.json`(본체 안 · git 에 안 올라감 · 최근 80개)에 한 줄로 남기고 [학습] 탭에는 안 뜬다. 같은 함정이 또 나오면(검토자가 "한 번 본 후보" id 를 `repeatOf` 에 적는다) 그때 이슈를 열고 "처음 본 곳"을 적는다. 이미 열린 이슈와 같은 함정이면 새 이슈 대신 그 이슈에 `- 반복 +1` 만 붙는다. 에이전트가 직접 올리는 후보(8절)는 이 기준을 거치지 않는다
- 사용자가 [학습] 탭에서 **[넣기]·[고쳐서 넣기]·[버리기]** 를 고른다. 넣으면 공책 끝 `## 학습` 절에 한 줄(`<!-- learn:<id> -->` 표시), 쉬운 설명 기록은 `docs/knowledge/learned/<id>.md` 에 남는다
- **[묶음 넣기]** — [학습] 탭 위쪽에 레포(공책)별로 열린 후보를 묶어 보여 준다(후보가 둘 이상인 공책만). 체크를 풀어 뺄 수 있고 [묶음 넣기]를 누르면 고른 것을 하나씩 [넣기]와 똑같이 넣는다(공책 위치 · 화면 범위 · 기존 줄 강화 · 학습 기록 · 이슈를 휴지통으로). **target · 공책에 넣을 문장 · 화면 범위 · 기존 줄 강화 대상이 모두 정확히 같은 후보만 하나로 합친다** — 대표 하나만 넣고 나머지는 학습 기록에 `## 덧붙임` 으로 남긴 뒤 휴지통으로(넣은·버린 수에는 세지 않는다). 뜻이 비슷한 정도는 합치지 않는다. 스킬 후보 · 정리 후보는 묶음에 없다(아래 카드에서 따로)
- 학습한 내용은 [학습] 탭에서 언제든 **수정·삭제**한다(삭제는 휴지통 — 되살릴 수 있다)
- 기록에는 **넣은 사람**(`approved_by` — 그 컴퓨터의 git 사용자 이름)이 남고, [학습] 탭 "학습한 내용" 오른쪽에 보인다
- 팀 공유(git 커밋)는 사용자가 "커밋해줘" 할 때 모아서
- 넣기·버리기 수를 센다 — 2~3주 뒤 넣기 비율을 보고 자동 반영 여부를 다시 정한다
- **Jev 중복 점검**(TypeSafe Jev — `scripts/lib/jev.mjs`, Jev 키를 등록한 사람만 — `docs/setup.md` 7-2): 현황판이 1분마다 열린 후보(공책 함정 · 강화·스킬·정리 후보 제외)를 공책 줄과 비교한다. 이미 담긴 내용이라는 판정이 아주 높으면(95% 이상) **휴지통으로 옮긴다** — 기존 줄은 공책에 그대로라 잃는 것이 없고, 후보 끝에 `## Jev 자동 버림` 절(겹친 줄·점수)을 남긴 뒤 옮긴다. 60% 이상이면 카드에 "기존 줄과 겹쳐 보여요" 만 보인다. [학습] 탭 위에 자동으로 버린 수·최근 것이 보이고, 잘못 버렸으면 `.board-trash/<날짜>/issues/` 에서 `issues/` 로 옮기면 돌아온다. **넣기·고치기·지우기는 Jev 가 하지 않는다**(공책은 모든 에이전트가 작업마다 읽는다)
- **배우기 검토 나란히 판정**: 검토자를 돌리기 전에 Jev 가 "다시 밟을 함정이 드러났나" 점수를 낸다. 지금은 **건너뛰지 않고 기록만** 한다 — `node scripts/lib/jev.mjs --report` 로 점수와 검토자가 실제 낸 후보를 나란히 보고, 놓치는 작업이 없을 기준선을 잡은 뒤 거름망으로 바꿀지 정한다

## 7. 공책이 길어지면 — 낡은 줄 정리 · 화면별로 나누기

공책은 모든 작업이 매번 읽는다. 틀린 줄은 잘못 이끌고, 길어지면 정말 중요한 함정이 묻힌다. 그래서 **들어오는 문(1~6절)** 에 더해 **나가는 문**을 둔다. 둘 다 지우지 않고 후보만 올린다 — 사람이 [학습] 탭에서 고른다.

### 7-1. 어디에 걸리나 — 공통과 화면

| 종류 | 예 | 어디에 | 언제 읽나 |
|---|---|---|---|
| **공통** — 레포 어디서든 밟는다 | 생성물 없으면 빌드 실패 · 페이지 번호 0부터 · Node 버전 · README 낡음 · 브랜치 규칙 | `gotchas.md` 본문 | 항상 전부 |
| **화면** — 그 폴더를 만질 때만 걸린다 | 주문 화면 `/orders` 같은 API 3번 호출 · `/settlements` 권한 가드 없음 · 배너 관리 이미지 업로드 | 나뉘기 전: 공통 공책에 `[화면 <폴더>]` 를 붙여 / 나뉜 뒤: `gotchas/<폴더>.md` | 작업할 파일이 그 폴더 안일 때 |

- **URL 이 아니라 코드 폴더**로 적는다(`app/orders` · `pages/auth` · `src/screens/tabs`). 폴더와 화면 주소가 다른 경우가 있다(예: `PaymentsDetailContainer` 는 `app/orders/` 에 있지만 `/settlements/[id]/payments` 에서 쓰인다)
- **애매하면 공통.** 안 읽어서 밟는 것보다 더 읽는 게 낫다
- 학습 후보의 `scope:` 가 이 판단이다. [넣기]는 화면 파일이 있으면 그리로, 없으면 공통 공책에 `[화면 <폴더>]` 를 붙여 넣는다

### 7-2. 언제 나누나 — 기준을 넘으면 "나눌까요?"

- **공통 공책이 2만 자**를 넘거나, 공통 공책에 **같은 화면 줄이 5개** 이상 모이면 정리 후보를 올린다(줄 수가 아니라 글자 수 — 한 줄 길이가 레포마다 다르다)
- [아테나에게 맡기기] → 아테나가 그 화면 줄만 `gotchas/<폴더 — / 는 ->.md`(예 `gotchas/app-orders.md`)로 **옮기기만** 한다(문장은 바꾸지 않는다, 학습 표시 `<!-- learn:… -->` 도 그대로 — 수정·삭제가 표시로 찾는다). `gotchas.md` 맨 위에 **화면 목차**(`## 화면별 함정` — 폴더 → 파일 · 줄 수)를 두고, 화면 파일 맨 위에는 `# <영역> 화면 <폴더> 함정` 과 "이 폴더를 만질 때 읽는다" 한 줄
- 자동으로 나누지 않는다

### 7-3. 낡은 줄 — 가리키는 파일이 사라졌으면 "지울까요?"

- `scripts/gotchas-check.mjs` 가 공책 줄의 백틱 파일 경로를 그 레포의 **운영 기준 브랜치** 파일 목록과 대조한다(`/sync` 끝 — 막 받아온 ref). 경로 끝이 같으면, 그래도 없으면 파일 이름이 어느 담당 레포에든 있으면 있는 것으로 본다(단 `page.tsx`·`index.ts` 처럼 서로 다른 경로 3곳 넘게 있는 흔한 이름은 줄에 적힌 폴더가 실제 경로에 순서대로 들어 있을 때만)
- 판단하지 않는 줄: 경로가 없는 줄 · 경로 바로 뒤(15자 안)에 "없음·삭제·존재하지" 처럼 원래 없다고 적은 경로 · 문서와 코드가 어긋난다고 적은 줄(낡·불일치·라고 적혀·↔) · 아테나 쪽 파일 · 별칭 import(`@x/…`)
- 공책마다 정리 후보 하나(`issues/<날짜>-<영역>-learn-gotchas-tidy.md`, `kind: tidy`)로 모인다. 줄마다 **[지우기]**(학습으로 들어온 줄이면 학습한 내용 삭제와 같다 — 기록은 휴지통) · **[그대로 두기]**(`.sync/gotchas-keep.json` 에 남아 같은 줄·같은 경로면 다음 점검부터 다시 올리지 않는다 — 줄이 바뀌면 다시 묻는다). 다 처리하면 후보가 닫힌다. 넣기·버리기 수에는 세지 않는다
- 파일이 사라졌다고 함정이 꼭 없어진 건 아니다(이름만 바뀌었을 수 있다). 지우기 전에 줄을 읽고, 옮겨졌으면 [그대로 두기] 후 줄을 고친다


## 8. 언제 올리나 · 어디에 담나 · 보고 블록 (2026-10-29 `AGENTS.md` 6절에서 옮김)

**읽을 때**: 학습 후보를 올리기 전 · 작업을 끝내며 보고 끝 "📚 배운 것" 을 쓸 때.

에이전트는 아래 **세 가지 순간**에 배운 것을 학습 후보(learn 이슈)로 올린다(`signal:`). 공책에는 사용자가 현황판 [학습] 탭에서 [넣기]를 고른 것만 들어간다.
- `done` **작업을 끝낼 때** — 보고 끝에 0~3줄. 끝낼 때는 **PR 을 올리고 보고할 때**(`ship.sh` — "PR 올려줘" 한 마디의 끝), 여러 레포 작업(PR 은 아테나가 올린다)이면 아테나에 넘기는 마지막 결과 보고, PR 없이 끝나는 작업(조사 · 확인)은 마지막 결과를 보고할 때다. 요청마다 붙이지 않는다
- `correction` **사용자가 바로잡을 때**("그거 아니야", "이렇게 해") — 가장 중요한 신호다. 그 레포 · 작업 방식에 대한 교정이면 그 자리에서 이슈를 만들고 한 줄로 알린다. 그 요청에만 해당하는 지시면 만들지 않는다
- `repeat-error` **같은 오류가 3번 날 때**(코드 규칙 "오류 대응") — 원인이 레포 고유 함정이면
- `review` **배우기 검토자** — **내 작업의 PR 이 모두 머지되면**(어느 브랜치로든 · 현황판이 5분마다 감지) 그 작업의 계획서(요청 · 결정 · 결과) · 대화 기록(줄여서 · 도구 결과 본문 빼고 · 비밀값 가림) · 머지된 PR 의 바뀐 코드 · 리뷰 댓글을 별도 Claude 가 읽고 빠진 것을 learn 이슈로 보탠다(`scripts/learn-review.mjs` — 역할은 `.claude/agents/learn-reviewer.md`, 뒤에서 도는 검토 하나가 차례로). 머지되지 않은 시도는 배우지 않는다. 에이전트가 이미 올린 것과 겹치면 덧붙이거나 건너뛴다 — 에이전트는 위 세 순간에 그대로 올린다

어디에 담나
- 아테나 자체 작업에서 배운 것은 `target: docs/knowledge/athena/gotchas.md#절`
- 아테나 루트의 `issues/<YYYYMMDD>-<영역>-learn-<이름>.md`(워크트리 pane 이면 아테나 루트 절대 경로로) — `repo: athena` · `kind: knowledge` · `signal:` · `basis: code | run`(근거가 사용자 말뿐이면 올리지 않는다 — 취향일 수 있다, 1-1) · `source: <계획서>` · `target: <docs/knowledge/<영역>/gotchas.md#절 | skill:<이름>>`(공책은 gotchas.md 만) · `scope: <코드 폴더>`(그 화면을 만질 때만 걸리면 — 예 `app/orders`, 레포 어디서든이면 생략) · 기존 줄을 고치는 것이면 `strengthen: <그 줄 그대로>`. 본문은 `## 무엇을 배웠나` · `## 왜 중요한가` · `## 공책에 넣을 문장` · `## 어디서 배웠나`(3절)
- 현황판 **[학습] 탭**에 뜬다(이슈 목록에는 안 뜬다). 공책 기존 줄과 같은 내용이라고 Jev 가 아주 높게 본 후보는 휴지통으로 저절로 빠진다(Jev 키를 등록한 사람만 · 6절). 사용자가 [넣기] · [고쳐서 넣기] · [버리기] — 넣으면 공책 끝 `## 학습` 절에 한 줄, 쉬운 설명 기록은 `docs/knowledge/learned/` 에 남고 [학습] 탭에서 언제든 수정 · 삭제
- 공책 · 스킬은 **직접 고치지 않는다.** 스킬 후보("🛠 스킬로 만들까요?")를 고르면 아테나가 만든다(`docs/extending.md` "학습으로 스킬 만들기")
