우리 아테나는 무엇이고,
Hermes Agent 와 무엇이 다른가

이름은 같지만 다른 도구다. 우리 아테나는 Claude Code 위에 규칙·에이전트·스크립트로 만든 FE 팀 작업 공간이고, Hermes Agent 에서는 "쓰면서 스스로 배우는" 학습 구조만 조사해서 우리 방식으로 가져왔다.

01한 줄 정리

처음 설명할 때 "Hermes Agent 를 도입했다"고 했다면 이렇게 바로잡는다.

Nous Research · Hermes Agent
혼자 쓰는 개인 AI 비서.
혼자 배우고 혼자 고친다.
  • 오픈소스 에이전트 — 자체 실행기 · 메신저 연결
  • 대화하다 보면 뒤에서 배울 것을 골라 바로 스킬·기억에 저장
  • 배운 것은 내 컴퓨터에만 있다
우리 · 아테나
회사 레포 여러 곳을 맡는 팀 리드.
스스로 알아차리고, 사람이 승인한다.
  • Claude Code 위에 만든 작업 공간 — 따로 설치할 것 없음
  • 요청 → 레포 고르기 → 계획서 → 담당 에이전트 → 리뷰 → PR
  • 배운 것은 사람이 [넣기]를 눌러야 들어가고, git 으로 팀 전체가 공유
정정 문장 예시 — "아테나는 우리가 Claude Code 로 만든 FE 팀 작업 도구고, 오픈소스 Hermes Agent 의 '스스로 배우는' 구조를 참고해서 학습 기능을 붙였습니다. Hermes Agent 를 설치한 건 아닙니다."

03아테나가 아는 것

매번 레포 전체를 읽지 않는다. 레포마다 정리해 둔 노트를 먼저 보고, 필요한 코드만 골라 읽는다. 노트와 코드가 다르면 코드를 믿는다.

아는 것적힌 곳누가 · 언제 채우나공유
폴더·화면 지도structure.md/sync — 운영에 배포된 코드 기준✅ 팀
레포 규칙rules.md/sync — 레포 안 규칙 문서가 바뀔 때✅ 팀
함정 (공책)gotchas.md학습 — [학습] 탭에서 [넣기]✅ 팀
예시 파일 · 절차patterns.md · workflows.md처음 만들 때 + /sync✅ 팀
나의 일하는 방식Claude 메모리Claude 가 대화에서 — 오래 유효한 운영 규칙만 (4절)❌ 나만
진행 중인 일plans/ · issues/작업하면서❌ 나만 → 끝나면 아카이브

/sync — 직접 칠 때만

운영 브랜치(팩 pack.json 의 레포별 branch)를 읽어 지난번 이후 바뀐 것만 노트에 반영한다. 확인되는 사실만 고치고 판단이 필요한 건 "확인 필요" 이슈로 묻는다. 배포 안 된 화면은 노트에 없다.

사람만 아는 것

"이 페이지는 영업팀이 ○○ 할 때 쓴다" 같은 업무 용도는 코드에 없다. 아테나에게 "○○ 페이지는 △△ 용도야, 지식 문서에 적어줘" 라고 하면 노트에 들어가고, 커밋하면 팀이 안다.

04학습 — Hermes Agent 에서 가져온 부분

밟은 함정을 다음 작업이 또 밟지 않게 레포별 공책(gotchas.md)에 적는다. 에이전트는 작업 전에 공책을 읽는다.

① 작업한 에이전트

언제 작업 끝(PR 미리보기) · 사용자가 바로잡을 때 · 같은 오류 3번

그 자리에서 학습 후보를 올린다. 맥락을 가장 잘 안다.

② 배우기 검토자

언제 내 작업의 PR 이 머지되면 자동

계획서 · 대화 · 최종 코드 · 리뷰 댓글을 읽고 빠진 것을 보탠다. 머지 안 된 시도는 배우지 않는다.

③ 사람

언제 아무 때나

현황판 [학습] 탭에서 [넣기] · [고쳐서 넣기] · [버리기]. 넣어야만 공책에 들어간다.

무엇을 배우나 — 셋을 모두 만족할 때만

  1. 다시 마주친다 — 그 레포의 평범한 다음 작업에서 또 만난다
  2. 모르면 실제로 잘못된다 — 잘못 고치거나 시간을 크게 버린다
  3. 코드만 봐서는 바로 알기 어렵다

그리고 근거가 코드나 실행 결과여야 한다. "사용자가 그렇게 말했다"뿐이면 취향일 수 있어 스크립트가 거른다. 대부분의 작업은 배울 게 0개 — 그게 정상이다.

✅ "이 앱의 QA 씬은 실제 요청을 직접 막아야 한다"(근거: 러너 코드) · ❌ "결정은 표로 보여 줘"(근거: 사용자 말뿐 → 각자 Claude 메모리)

학습은 두 가지 — 저장 규정이 다르다

현황판 [학습] 탭이 둘로 나뉘는 이유. 아테나 학습은 팀 공책에, 클로드 학습은 내 컴퓨터의 Claude 메모리에 쌓인다. 둘 다 "아무거나 저장하지 않는다"가 원칙이지만, 지키는 방법이 다르다.

🧭 아테나 학습🧠 클로드 학습
무엇을레포 코드의 함정 — "이 레포에서 모르면 당하는 것"나와 일하는 방식 · 오래 유효한 운영 규칙
어디에레포 공책 gotchas.md 끝 ## 학습 절 + 쉬운 설명 docs/knowledge/learned/~/.claude/projects/…/memory/ — 한 파일에 한 가지 + 목차 MEMORY.md
누가 보나팀 전체 — 커밋하면 git 으로나만 — 레포에 안 올라간다
누가 저장을 정하나에이전트·검토자가 후보만 올리고, 사람이 [넣기]Claude 가 대화 중에 판단해 저장 (승인 단계 없음)
근거코드·실행 결과로 확인된 것만. "사용자가 말했다"뿐이면 스크립트가 거른다내 말이 근거 — 교정("그거 말고")이나 확인해 준 방식
저장 안 하는 것이미 코드로 고친 버그 · 한 번 있었던 일 · 서버·인프라 원인 · 취향 · 상식 · 아직 안 고친 버그(→ 이슈)버전·라이브러리·구조 · 경로·포트·엔드포인트 · 진행 단계·현재 작업 · 브랜치·워크트리 · 완료 여부 · 구현 결정 — "오래 쓸 것 같은 결정"도 예외 없음
고치기·지우기[학습] 탭 "학습한 내용"에서 수정·삭제[학습] 탭 "클로드 학습"은 보기만 — 지우려면 Claude 에게 "그 메모리 지워줘"
아테나 학습이 엄격한 방법 — 문 4개
  1. 세 조건을 모두 — 다시 마주친다 · 모르면 실제로 잘못된다 · 코드만 봐선 모른다
  2. 근거 필터 — 근거가 사용자 말뿐인 후보는 사람이 보기 전에 스크립트가 기계적으로 버린다
  3. 사람 승인 — [넣기]를 누른 것만 공책에. 넣기·버리기 비율도 센다
  4. 중복 금지 — 같은 내용이 있으면 새 줄 대신 기존 줄을 고친다

왜: 모든 작업이 매번 읽는 팀 공용 문서라서 잘못된 한 줄이 모두에게 퍼진다.

클로드 학습이 엄격한 방법 — 금지 목록
  1. 장기 운영 규칙만 — 프로젝트가 바뀌어도 유효한 것. 예: "되돌릴 수 없는 삭제는 먼저 확인", "요청한 것만"
  2. 사실은 금지 — 버전·경로·진행 상황처럼 바뀌는 사실은 계획서·지식 노트가 맡는다
  3. 지난 대화는 단서로만 — "왜 그랬나"를 찾을 때만 보고, 승인·완료의 증거로 쓰거나 메모리로 옮기지 않는다
  4. 있으면 고치고, 틀리면 지운다 — 같은 메모리를 새로 만들지 않는다

왜: 메모리는 매 세션 자동으로 들어오는데 사실이 바뀌어도 저절로 고쳐지지 않는다. 옛 사실이 남으면 지금 코드보다 그걸 믿게 된다. 단, 자동 저장을 도구로 막을 수는 없어 규칙으로 지키고 새 세션에서 눈으로 확인한다 (정본 AGENTS.md 2.5).

공책이 길어지면 — 나가는 문

🧹 낡은 줄 정리

/sync 끝에 공책 줄이 가리키는 파일이 운영 코드에 아직 있는지 본다. 사라졌으면 [학습] 탭에 정리 후보 — 줄마다 [지우기] · [그대로 두기].

🖥 화면별로 나누기

레포 어디서든 밟는 함정은 공통(항상 읽음), 한 화면 폴더에만 걸리면 화면(그 폴더 작업 때만). 공통 공책이 2만 자를 넘거나 같은 화면 줄이 5줄 모이면 "나눌까요?" → gotchas/<폴더>.md

둘 다 지우지 않고 후보만 — 사람이 고른다. 들어오는 문(조건 · 근거 · 승인)과 짝이다.

한 문장으로 — 아테나 학습은 "팀이 믿을 수 있는 코드 사실만, 사람이 골라서", 클로드 학습은 "나에 대한 오래 가는 규칙만, 바뀌는 사실은 절대 안 넣고".

06왜 통째로 들이지 않았나

🧱 Claude Code 위에 서 있다

서브에이전트 · 훅 · 스킬 · pane 디스패치가 모두 Claude Code 기능이다. 갈아타면 처음부터 다시 만들어야 하고, 같이 쓰면 시스템이 둘이 된다.

🔒 안전장치가 빠진다

회사 코드와 토큰이 있는 맥에서, 스스로 스킬을 쓰고 고치는 에이전트를 돌리면 커밋·PR·토큰 규칙이 적용되지 않는다.

👥 공책은 팀 공용이다

모든 작업이 매번 읽는 문서다. 잘못 배운 한 줄이 들어가면 그 뒤 작업이 모두 그걸 믿는다. 그래서 사람이 승인한다.

넣기·버리기 비율을 세고 있다. 믿을 만한 숫자가 쌓이면 가벼운 것은 자동으로 넣는 쪽으로 다시 정할 수 있다.

07자주 받는 질문

Hermes Agent 를 설치해야 하나요?

아니요. 레포를 받고 claude 를 켜면 끝이다. 레포 연결도 알아서 한다.

그럼 "아테나"라고 불러도 되나요?

우리 도구 이름이 아테나다. 다만 "Hermes Agent 를 도입했다"가 아니라 "학습 구조를 참고했다"가 맞다.

내가 배운 것이 팀에 바로 퍼지나요?

[넣기] 후 "커밋해줘" 해서 main 에 올라가면 팀 전체가 다음 작업부터 읽는다. 그 전엔 내 컴퓨터에만 있다.

잘못 배운 건 어떻게 지우나요?

현황판 [학습] 탭 → "학습한 내용"에서 고치거나 지운다. git 기록이 있어 되돌릴 수도 있다.

내 말버릇·취향도 배우나요?

공용 공책엔 안 들어간다. 그런 건 각자 Claude 메모리가 맡는다. 다만 메모리에도 오래 유효한 운영 규칙만 남긴다(4절). [학습] 탭 "클로드 학습"에서 본다.
