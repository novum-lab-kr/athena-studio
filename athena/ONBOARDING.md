# 아테나 시작 가이드 (팀원용)

아테나는 프론트엔드 레포 여러 개를 한 곳에서 다루는 **Claude Code 워크스페이스**다. 이 폴더에서 `claude` 를 켜면 팀 리드 **아테나**가 되고, 요청을 받아 어느 레포 일인지 고르고 → 계획서를 쓰고 → 담당 FE 에이전트에게 맡기고 → 리뷰까지 받아 보고한다. 레포마다 정리해 둔 지식 노트로 일하고(5절), 작업하면서 알게 된 레포 함정은 **학습**해서 다음 작업에 쓴다(6절).

> Nous Research 의 오픈소스 **Hermes Agent** 와는 다른 것이다(예전 이름 "헤르메스"가 같았을 뿐). 따로 설치하지 않는다 — Claude Code 위에 우리가 만든 규칙·스크립트 묶음이다.

이 문서는 **처음 받아서 쓰기 시작할 때까지**만 다룬다. 기능 전체 설명은 `README.md`, 규칙은 `AGENTS.md`·`CLAUDE.md`, 화면으로 보는 사용법은 `docs/playbook.html`(터미널에서 `/guide 열기`).

---

## 1. 준비물

| 도구 | 용도 | 없으면 |
|---|---|---|
| **Claude Code** (`claude`) | 아테나·에이전트 본체 | 동작 안 함 |
| `git`, `python3` | 셋업·훅·스크립트 | 동작 안 함 |
| **Node** + `nvm` | 검증 스크립트·현황판·QA. 레포마다 `.nvmrc` 버전이 다르다 | 검증이 경고·실패 |
| `pnpm` | 레포 설치·빌드 | 검증·빌드 불가 |
| **`gh`** (GitHub CLI, `gh auth login` 완료) | `ship.sh` 의 push·draft PR, 현황판의 PR 머지 감지 | PR 을 못 올린다 |
| **Athena Studio** (데스크톱 앱) | 아테나 코어를 들고 와 풀고, 에이전트를 옆 pane 에 띄워 보이게 일 시킨다 · 현황판 · 에이전트 모니터 | 앱 밖 터미널이면 `/call`·디스패치가 "직접 실행하세요" 안내만 한다. 현황판은 백그라운드로 뜬다 |

추가로 레포 쪽 권한이 필요하다.
- 담당 레포들의 GitHub 접근 권한
- (회사에 사내 발행 패키지가 있으면) **패키지 레지스트리 읽기 토큰** — 팩 안내(`pack/ROUTING.md`)를 따른다. 레포 `.npmrc` 가 아니라 **`~/.npmrc` 에** 넣는다. 토큰 값은 어디에도 붙여 넣거나 공유하지 않는다
- **claude.ai 계정에 Atlassian 커넥터 연결**(설정 → Connectors) — 아테나와 모든 FE 에이전트·reviewer 가 Jira 티켓·Confluence 기획서를 **읽는다**(쓰기는 없다 — 이슈 생성·댓글은 사람이)
- 레포마다 `.env` — 각 레포 안내대로 만든다(일부는 `pnpm gen:env`, AWS 자격 필요). 워크트리를 만들 때 메인 체크아웃의 `.env*` 가 자동 복사된다
- (선택) **TypeSafe Jev 키 — 각자 본인 키**(https://console.typesafe.ai/keys, 유료 · 사용량은 키 주인에게 청구). 첫 실행 때 아테나가 묻고, 키가 나중에 생기면 아테나에게 "Jev 키 등록해줘" 라고 한다 — 옆에 뜨는 입력 창에 직접 붙여 넣는다(대화창에 넣지 않는다 · 터미널에서 `node scripts/jev-key.mjs` 도 같다). 넣으면 QA 실패 원인 추정 · 학습 후보 중복 자동 버리기 · 배우기 검토 나란히 판정이 켜진다(`docs/knowledge/common/learning.md` 6절). **없으면 지금처럼 Jev 없이 그대로 돈다.** 남의 키를 빌려 쓰거나 나눠 주지 않는다. 잠깐 끄려면 `ATHENA_JEV=off`

## 2. 설치

### 2-1. Athena Studio 를 켠다
**아테나 코어는 Athena Studio 앱이 들고 온다** — 따로 받거나 설치할 것은 없다. 처음 켜면 앱이 코어를 스튜디오 집에 풀고 창을 연다.

```
~/.athena-studio/core          주 본체(아테나 코어 · git 저장소 · main)
~/.athena-studio/bodies/<id>   팩 본체(팩마다 하나 — 코어가 만든다)
~/.athena-studio/data          데이터 폴더(팩 · 계획서 · 이슈 · 학습 대기열 · 백업)
```

코어 업데이트도 앱과 함께 온다 — 새 앱을 켜면 앱이 `bin/athena update --from <번들>` 로 본체마다 맞춘다(일하는 본체는 건너뛰고 다음에).

### 2-2. 팩과 담당 레포
담당 레포 목록은 **팩**의 `pack.json`(사람이 읽는 표는 `pack/ROUTING.md`)에 있다. 팩은 앱의 팩 메뉴(`▣ <팩> ▾`)·시작 화면에서 고른다.
- **팩이 있는 회사** — [팩 가져오기](압축 파일 · 팩 폴더 · git 레포)
- **새 회사** — [새 팩 만들기] → 그 본체에서 아테나를 켜면 `/setup` 이 레포 찾기부터 안내한다

담당 레포는 `reposRoot`(스튜디오는 홈 폴더) 아래에 clone 해 둔다. 자기가 맡지 않는 레포는 없어도 된다. 그 레포 담당 에이전트만 동작하지 않는다.

### 2-3. 켜기
창의 `athena` 작업 공간 pane 에서 `claude`(또는 `codex`)를 켠다. 팩이 없으면 `/setup` 이 레포 찾기부터 안내한다.
첫 화면에서 "현황 알려줘" 라고 해 보면 레포별 브랜치·변경 상태가 나온다. 여기까지 되면 준비 완료.

> 따로 셋업하지 않아도 된다. `claude` 를 켜면 `reposRoot` 아래의 담당 레포를 찾아 `repos/<레포>` 로 알아서 연결하고, 못 찾은 레포가 있으면 아테나가 위치를 묻는다.

**Studio 창 안에서 켜면 화면이 저절로 잡힌다** — 현황판은 뒤에서 뜨고(앱 📋 현황판 탭이 보여 준다), 에이전트 로그는 작업 창 가운데 맨 아래 🛰 AGENT MONITOR 칸이 보여 준다. 오른쪽 Explorer 에서 바뀐 파일을 누르면 diff 가 뜬다. 배우기 검토는 대기열이 생기면 뒤에서 돌고, 가이드 메뉴는 `/guide` 로 부를 때만 뜬다. `scripts/athena-up.sh` — 손으로 다시 돌려도 된다. 작업 창에서는 레포마다 **작업 공간(workspace)**, 그 안에 **탭**, 탭 안에 **pane** 이 있다.

**QA 를 돌릴 때만** 한 번 `scripts/setup.sh` 를 돌린다 — Playwright·Chromium 을 설치하고 도구(node·pnpm·claude…)도 점검해 준다.

## 3. 처음 써 보기

### 그냥 말한다 (기본)
담당 레포를 몰라도, 여러 레포에 걸쳐도, 버그 원인 찾기여도 그냥 말하면 된다.

> "주문 관리 목록 페이지네이션이 두 번째 페이지에서 비어 보여. 원인 찾아줘"
> "shop-web·admin-web 에 공지 배너 똑같이 넣어줘"

아테나가 하는 일
1. **어느 레포인지 고른다.** 팩 라우팅(`pack/ROUTING.md`)으로 고르고, 같은 말이 여러 레포를 가리키면 되묻는다
2. **계획서를 만들고 규모를 한 줄로 알린다** — `📋 경량으로 진행합니다 …` 또는 `📋 정식으로 진행합니다 …`
   - **경량**(문구·버그 하나·조사): 지시가 곧 승인. 바로 진행
   - **정식**(새 기능·여러 레포·API·구조 변경): 브라우저에 **결정 콘솔**이 열린다. 선택지를 고르고 **[이대로 진행]** 을 눌러야 시작한다. "추천대로"·"D2 는 B" 처럼 말로 답해도 된다
   - 정식이어도 급하면 "바로 고쳐" — 경량으로 바로 간다
3. **작업 브랜치·워크트리를 만든다**(`.worktrees/<레포>/<브랜치>`). 메인 체크아웃은 건드리지 않으니 미커밋 변경이 있어도 된다
4. **담당 에이전트를 옆 pane 에 띄운다** — 이름이 `🤖 <에이전트> · <브랜치>`

### 담당을 알면 `/call`
```
/call <에이전트>
```
아테나가 브랜치(기존 작업 이어 쓰기 / 새 브랜치)를 묻고 워크트리를 만든 뒤, 그 레포 workspace 에 에이전트 pane 을 띄운다. 이후 요청은 **그 pane 에서 직접** 한다.

### pane 에서 끝까지
레포 하나짜리 작업은 에이전트 pane 에서 끝난다.

| 말 | 일어나는 일 |
|---|---|
| (요청) | 작업 → 검증 스크립트 결과 표 보고 → 정식 계획서면 **자동 리뷰**(옆에 reviewer pane) · 경량이면 "리뷰할까요?" |
| "리뷰해줘" | 옆에 reviewer pane — 같은 트리로 이미 통과한 검증은 다시 돌리지 않는다(`♻️ 재사용`) |
| "커밋해줘" | `commit.sh` — 지정 파일만, 엄격 검증 통과해야 커밋. 계획서에 기록 |
| "PR 올려줘" | 한 마디로 끝 — 커밋 안 된 작업을 `commit.sh` 로 커밋하고, 작업 내용으로 제목·본문을 정리해 묻지 않고 **draft PR**(`ship.sh` · base 는 `prBase`) |

에이전트는 직접 `git commit`·`git push`·`gh pr create` 를 못 한다(보호 훅). 커밋·PR 은 **말했을 때만** 일어난다. 여러 레포에 걸친 작업의 push·PR 은 아테나가 순서를 정해 올린다.

## 4. 현황판 (`/board`)

```
/board
```
브라우저에 `localhost:4700` 이 열린다.
- **이슈**(첫 화면) — 해결할 이슈 목록(작업 중 찾았지만 그 자리에서 안 고친 것 · `issues/*.md` · 학습 후보 제외). [작업 시작] 으로 맡기고, 시작한 이슈는 맡은 pane 이 보인다
- 계획서 진행은 Studio 의 [작업] 팝업과 pane 머리 줄 [상세] 에서 본다. 계획서의 PR 이 모두 머지되면 자동으로 완료로 간다
- **QA 탭** — 서비스 → 층 → 흐름별 TC 결과. 레포 `docs/flows/` 의 TC 를 로컬 서버에 대고 돌린다([실행] · `/sync` 뒤 자동)
- 탭은 **이슈 · QA · 학습 · 아카이브 · 지표**
- **[학습] 탭** — **아테나 학습**(작업하며 알게 된 레포 함정 → 서비스별 공책, 후보를 [넣기]·[버리기], 학습한 내용 수정·삭제) / **클로드 학습**(Claude Code 메모리 — 대화에서 기억한 일하는 방식, 이 컴퓨터에만 있음, 읽기 전용)
- 끝난 일은 현황판이 자동으로 보관하고(머지 · 배우기 검토 · pane 닫힘 뒤), 지난 일은 **[아카이브] 탭**에서 찾는다

끄기: `/board stop`

## 5. 아테나가 아는 것

아테나는 일할 때마다 레포 코드를 처음부터 다 읽지 않는다. **레포마다 미리 정리해 둔 지식 노트를 먼저 보고, 필요한 코드만 골라 읽는다.** 노트가 정확할수록 빠르고 정확해진다.

### 무엇을 어디에 알고 있나

| 아는 것 | 적혀 있는 곳 | 누가·언제 채우나 | 팀과 공유 |
|---|---|---|---|
| 레포 폴더·화면(라우트) 지도 | `docs/knowledge/<레포>/structure.md` | `/sync` — 운영에 배포된 코드 기준 | ✅ |
| 레포 규칙("이건 꼭 지켜") | `…/rules.md` | `/sync` — 레포 안 규칙 문서가 바뀔 때 | ✅ |
| 함정("모르면 당한다") | `…/gotchas.md` | **학습** — 작업하다 알게 된 걸 [학습] 탭에서 [넣기] + `/sync` | ✅ |
| 따라 할 예시 파일·작업 절차 | `…/patterns.md` · `workflows.md` | 처음 만들 때 + `/sync` | ✅ |
| 나의 일하는 방식("표로 보여 줘") | Claude 메모리(`~/.claude/…`) | Claude 가 대화에서 알아서 | ❌ 나만 |
| 진행 중인 일 | 계획서(`plans/`)·이슈(`issues/`) | 작업하면서 | ❌ 나만 (끝나면 자동 보관으로 팀에) |

### 어떻게 꺼내 쓰나 — 예: "결제 페이지 프로모션 배너 고쳐줘"
1. **어느 레포인지** — 팩 라우팅 규칙으로 레포·에이전트를 고른다. 갈리면 되묻는다
2. **어느 화면인지** — `structure.md` 의 화면 지도 → 실제 코드 → 화면 문구로 검색. 후보가 여럿이면 되묻는다
3. **맡긴다** — 찾은 파일 경로를 계획서에 적어 담당 에이전트에게. 에이전트는 시작 전에 그 레포의 `rules.md` 필수 절과 `gotchas.md` 를 전부 읽는다

**문서와 코드가 다르면 코드를 믿는다.** 노트는 길잡이이고, 정답은 언제나 지금 코드다.

### 언제 최신이 되나 — `/sync`
- **운영에 배포된 코드**(팩 `pack.json` 의 레포별 `branch`)를 읽어 **지난번 이후 바뀐 것만** 노트에 반영한다
- 자동으로 돌지 않는다 — 누군가 `/sync` 를 돌릴 때(가끔, 한 사람이)
- **확인되는 사실만 고치고**(새 화면·버전·명령), 판단이 필요한 문장은 고치지 않고 "확인 필요" 이슈로 묻는다
- 그래서 **아직 배포 안 된 화면은 노트에 없다** — 그런 화면은 작업할 때 코드에서 직접 찾는다

### 아테나가 혼자서는 알 수 없는 것 — 사람이 채워 준다
- **화면의 업무 용도** — "이 페이지는 영업팀이 제휴사 고객 번호를 한꺼번에 조회할 때 쓴다" 같은 건 코드에 없다
- **코드 밖의 운영 규칙** — 어느 팀이 쓰는지, 언제 쓰면 안 되는지 같은 것

알려 주는 법: 아테나에게 **"○○ 페이지는 △△ 용도야. 지식 문서에 적어줘"** — `structure.md` 화면 설명에 "사용자 확인" 표시와 함께 들어가고, 커밋하면 팀 전체가 안다. 학습 기능은 근거가 "사용자가 말했다"뿐인 후보를 취향일 수 있다고 보고 거르므로, 이런 업무 지식은 이렇게 직접 적어 달라고 하는 게 확실하다.

## 6. 학습 — 아테나가 배우는 방법

작업하다 밟은 함정을 다음 작업이 또 밟지 않게, 아테나가 **배운 것을 서비스별 공책(`gotchas.md`)에 적어 둔다.** 에이전트는 작업 전에 이 공책을 읽는다.

```
작업 중·작업 끝  ──▶  학습 후보  ──▶  [학습] 탭에서 내가 고른다  ──▶  공책에 한 줄  ──▶  다음 작업이 읽는다
```

### 누가 배우나 — 셋이 나눠 맡는다

| 누가 | 언제 | 하는 일 |
|---|---|---|
| **작업한 에이전트** | 작업을 끝낼 때(PR 미리보기) · 사용자가 바로잡을 때 · 같은 오류가 3번 날 때 | 그 자리에서 "다음에도 밟을 것"을 학습 후보로 올린다. 맥락을 가장 잘 안다 |
| **배우기 검토자**(별도 Claude · 역할 문서 `.claude/agents/learn-reviewer.md`) | **내 작업의 PR 이 머지되면** 자동으로(어느 브랜치로든) | 그 작업의 **계획서(요청·결정·결과) · 대화 · 최종으로 바뀐 코드 · PR 리뷰 댓글**을 읽고 에이전트가 빠뜨린 것을 보탠다. 팀이 받아들인 결과로 배우고, 머지 안 된 시도는 배우지 않는다. "📚 배우기 검토" pane 이 하나 뜬다(끝나면 닫아도 된다 · 한 번에 약 $0.1~0.4, 구독이면 사용량에서) |
| **사람(나)** | 아무 때나 | 현황판 **[학습] 탭 → 🧭 아테나 학습**에서 후보를 읽고 **[넣기]·[고쳐서 넣기]·[버리기]**. 넣어야만 공책에 들어간다 |

### 무엇을 기준으로 고르나 — 셋을 모두 만족할 때만
1. **다시 마주친다** — 그 레포에서 평범한 다음 작업을 하다가 또 만날 것
2. **모르면 실제로 잘못된다** — 잘못 고치거나, 사고를 내거나, 시간을 크게 버린다. "모르면 무엇이 잘못되나"를 구체적으로 쓸 수 있어야 한다
3. **코드만 봐서는 바로 알기 어렵다**

그리고 **근거가 코드나 실행 결과로 확인돼야 한다.** "사용자가 그렇게 말했다"뿐이면 취향일 수 있으니 공용 공책에 넣지 않는다 — 이건 사람의 판단이 아니라 스크립트가 기계적으로 거른다.

**학습하지 않는 것**: 이번 작업에서 이미 코드로 고친 버그 · 한 번 있었던 문의·장애 · 원인이 서버·인프라인 것 · 일하는 스타일·취향(→ 각자 Claude 메모리, **클로드 학습**) · 일반 상식

예: ✅ "이 앱의 TC 는 쓰기 요청을 mock 으로 막아야 한다"(근거: 그 앱 API 코드가 실제 데이터를 바꾼다) / ❌ "결정은 표로 보여 줘"(근거: 사용자 말뿐 — 취향)

**대부분의 작업은 학습할 게 0개다. 후보가 적은 게 정상이다.** 후보에는 무엇을 배웠나 · 왜 중요한가 · 공책에 들어갈 문장 · 어디서 배웠나가 **쉬운 말로** 적혀 온다. 넣은 것은 [학습] 탭 "학습한 내용"에서 언제든 고치거나 지운다. 팀과 나누려면 아테나에게 "커밋해줘". 기준 전체: `docs/knowledge/common/learning.md`

### 공책이 길어지면 — 정리하고 나눈다
- **낡은 줄**: `/sync` 끝에 공책 줄이 가리키는 파일이 운영 코드에 아직 있는지 확인한다. 사라졌으면 [학습] 탭에 "🧹 공책 정리 후보"로 올라오고, 줄마다 **[지우기]·[그대로 두기]** 를 고른다(파일 이름만 바뀌었을 수 있으니 읽고 고른다)
- **화면별로 나누기**: 함정은 "어디에 걸리나"로 나눈다 — 레포 어디서든 밟으면 **공통**(항상 읽는다), 특정 화면 폴더를 만질 때만 걸리면 **화면**(그 폴더 작업 때만 읽는다). 공통 공책이 **2만 자**를 넘거나 같은 화면 줄이 **5개** 모이면 "나눌까요?" — [아테나에게 나누기 맡기기]를 누르면 그 화면 줄만 `gotchas/<폴더>.md` 로 옮긴다
- 둘 다 **지우지 않고 후보만** 올린다. 지금은 기준을 넘는 공책이 없다

### Nous Research 의 Hermes Agent 와 무엇이 다른가

"스스로 배우는" 아이디어는 오픈소스 Hermes Agent 의 학습 구조를 조사해 가져왔다. 코드는 가져오지 않았고, 팀이 같이 쓰는 공책이라는 점에 맞춰 다르게 만들었다.

| | Hermes Agent | 우리 아테나 |
|---|---|---|
| 누가 배우나 | 배우기 전용 에이전트가 뒤에서 | 작업한 에이전트 + 배우기 검토자, **최종은 사람** |
| 언제 | 대화 10번·도구 10번마다 자동 | 작업 끝 · 사용자 교정 · 같은 오류 3회 · **PR 머지 뒤**(리뷰 댓글까지 보고) |
| 저장 | **바로 저장**(사람 확인 없음) | **[넣기]를 누른 것만** |
| 무엇을 | 스킬·기억 | 레포 함정(공책). 반복 절차는 "스킬로 만들까요?"라고 묻는다 |
| 취향 | 같이 기억 | 공용 공책엔 안 넣고 각자 Claude 메모리로 |
| 근거 확인 | LLM 이 판단 | 코드·실행 결과로 확인된 것만(스크립트가 거른다) |
| 공유 | 내 컴퓨터 | git 으로 팀 전체 |
| 지난 대화 검색 | 있음 | 없음 |

**왜 사람이 승인하나** — 공책(`gotchas.md`)은 모든 작업이 매번 다 읽는 팀 공용 문서다. 잘못 배운 한 줄이 들어가면 그 뒤 모든 작업이 그걸 믿고, 쓸데없는 줄이 쌓이면 정말 중요한 함정이 묻힌다. 넣기·버리기 비율을 세고 있으니, 믿을 만하다는 숫자가 나오면 자동으로 넣는 쪽으로 다시 정할 수 있다.

## 8. 꼭 지킬 것

- **토큰·키·비밀번호는 어디에도 출력하지 않는다.** `.npmrc`·`.env*` 내용, `printenv`, `ps aux` 등을 아테나에게 보여 달라고 하지 않는다. 훅이 흔한 경로를 막지만 규칙이 우선이다. 실수로 노출되면 바로 폐기·재발급
- **무거운 명령은 한 번에 하나.** install·build·dev·tsc·test 는 `scripts/heavy.sh` 로 줄을 선다(에이전트는 알아서 쓴다). 직접 돌릴 때도 앞에 붙인다. 동시 빌드로 컴퓨터가 멈춘 적이 있다
- **계획서 없이 작업하지 않는다.** 아테나·`/call` 이 알아서 만든다. 계획서(`plans/`)는 각자 로컬에만 있다(gitignore). 공유되는 것은 끝나서 보관한 일(`archive/` — 팩 레포에 커밋된다)
- 담당 범위 밖(팩 `pack.json` 에 없는 레포 등)은 수정하지 않는다
- 학습 후보는 **[학습] 탭에서 [넣기]를 눌러야** 공책에 들어간다. 취향이 섞인 후보는 [버리기]
- 아테나 자체(이 레포)를 고치면 `main` 에 커밋·push 한다. 에이전트·스킬을 추가했다면 `docs/extending.md` 의 "같이 갱신할 곳"을 따른다
